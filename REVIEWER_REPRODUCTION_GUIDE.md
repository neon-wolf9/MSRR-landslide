# Reviewer reproduction guide — v1.0.1 code and deposited data

This guide distinguishes runnable software checks from the formal real-data workflow. Run commands from the repository root in the environment specified by `environment.yml`. The eleven frozen derived study files and historical hand-offs are available separately at [Zenodo DOI 10.5281/zenodo.23533084](https://doi.org/10.5281/zenodo.23533084). No command below that trains or evaluates the manuscript models was executed to prepare this guide.

## A. Runs now, without scientific data

```bash
conda env create -f environment.yml
conda activate msrr-landslide
python examples/minimal_msrr_example.py
python scripts/00_check_environment.py
python scripts/01_verify_inputs.py
python scripts/15_verify_reference_results.py
python -m pytest -q -p no:cacheprovider
```

The example uses eight **synthetic** three-member sets and the canonical 120B transform. Expected shapes are `(8,3,792)` RAW and `(8,3,2446)` MSRR. It also checks the StrictPair and Edge calculation interface. The tests check frozen file/reference integrity, 5,056/1,692 replay memberships, five-fold invariants, and the canonical all-or-none matching solver on invented legal edges. No model is trained and no Hiroshima/Kyushu manuscript score is regenerated by these commands.

`scripts/01_verify_inputs.py` without `--full` reports which model-ready paths are not yet present in the checkout and exits successfully when package metadata are present. Download `MSRR_CG_approved_data_candidate.zip` from the Zenodo record, extract it at the repository root without changing paths, and verify `metadata/SHA256SUMS.txt` using the command in `README.md`. Its `--full` option checks **only seven** of the deposited inputs; a zero exit is not a complete formal-workflow dependency gate. The additional pair files and row-level hand-offs are also in the deposit, but source-to-benchmark reconstruction requires separately acquired raw products and other workflow-specific intermediates.

For static review of reported outcomes, use `RESULT_MANIFEST.csv` and `docs/PAPER_RESULT_MAP.md` to locate the frozen OOF metrics, eight score arrays, paired-bootstrap summaries, Kyushu metrics and exact-replay evidence under `reference_results/`. The hash checker verifies their distributed bytes; it does not recalculate them.

## B. Formal scientific workflow — input map, not a rerun claim

1. Restore the published Zenodo ZIP and verify its eleven study-file SHA-256 values. Use `docs/DATA_ACQUISITION.md`, `docs/DATA_SOURCES.md`, and the frozen manifests for any upstream raw-product acquisition; do not assume a current provider snapshot is equivalent to the study asset.
2. Check the additional exact-path preflight inputs and preserved 120B/124D historical hand-offs before each downstream script. The original code modules and frozen configurations are in this code release. The formal 120B entry refuses to overwrite a nonempty output directory; a separately authorized rerun needs a distinct clean execution checkout, while the published historical hand-offs should be retained unchanged for inspection and downstream input-layout checks. Historical outputs are not proof of a newly executed run.
3. For a separately authorized scientific rerun, record environment/source hashes, seeds, fold membership and output paths. Only then consider the formal entry points in this order:

   ```bash
   python scripts/01_verify_inputs.py --full
   python scripts/127_AUDIT_MATCHING_PROTOCOL_REPRODUCIBILITY.py
   python scripts/130_AUDIT_ORIGINAL_BENCHMARK_EXACT_REPLAY.py
   python scripts/120B_RUN_MSRR_CROSS_BACKBONE_5FOLD_NO_LIGHTGBM_ONE_SHOT.py
   python scripts/121_RECOVER_OOF_AND_PAIRED_BOOTSTRAP.py
   python scripts/124D_RUN_KYUSHU2017_FROZEN_EXTERNAL_VALIDATION.py
   ```

   These are **not** lightweight review commands; they read real event data and the later commands train/evaluate models or perform formal inference. Their presence here maps the authority chain, not permission or evidence that they were run in this audit. `127`/`130` also require substantial intermediate/source data beyond the seven model-ready files.

## Interpretation and acceptance boundary

- RAW has 92 static plus 70 × 10 rainfall features = **792**; MSRR is **2446**. The transform uses shared set mean, signed and absolute deviations, and rainfall-residual summaries; it does not use roles/labels to construct features.
- Hiroshima has 5,056 complete 1-positive/2-hard-control sets and five spatial folds; Kyushu has 1,692 complete external sets. A hard control is not a verified permanent non-landslide location.
- AUROC/AUPRC use pooled row scores; StrictPair and Edge assess matched-set ordering. Frozen published values are in `reference_results/`, but independent confirmation requires the input and execution closure above.
- The code release supports software inspection and light synthetic evaluation; the separate Zenodo deposit supplies frozen derived inputs and hand-offs for stronger independent assessment. A complete source-data-to-results rerun was not performed during release preparation, and upstream raw-product or workflow-specific intermediate requirements must be checked before asserting end-to-end regeneration.
