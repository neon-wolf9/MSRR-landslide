# Reviewer reproduction guide — current public-candidate boundary

This guide distinguishes runnable software checks from the **currently blocked** real-data workflow. Run commands from the repository root in the environment specified by `environment.yml`. No command below that trains or evaluates the manuscript models was executed to prepare this guide.

## A. Runs now, without scientific data

```bash
conda env create -f environment.yml
conda activate msrr-landslide
python examples/minimal_msrr_example.py
python scripts/00_check_environment.py
python scripts/01_verify_inputs.py
python scripts/15_verify_reference_results.py
python -m pytest -q -p no:cacheprovider
```

The example uses eight **synthetic** three-member sets and the canonical 120B transform. Expected shapes are `(8,3,792)` RAW and `(8,3,2446)` MSRR. It also checks the StrictPair and Edge calculation interface. The tests check frozen file/reference integrity, 5,056/1,692 replay memberships, five-fold invariants, and the canonical all-or-none matching solver on invented legal edges. No model is trained and no Hiroshima/Kyushu manuscript score is regenerated by these commands.

`scripts/01_verify_inputs.py` without `--full` reports the unavailable model-ready data files but exits successfully when the package metadata are present. In the unpublished local candidate, one of seven real-data paths is present; the public GitHub package still lacks all seven. Its `--full` option checks **only those seven paths**. A successful `--full` result, if the six were later supplied locally, would **not** certify that 120B, 121 or 124D can run; two more real pair files remain. The exact 120B frozen-output hand-off is now staged locally; see `WORKFLOW_HANDOFF_AUDIT.md`.

For static review of reported outcomes, use `RESULT_MANIFEST.csv` and `docs/PAPER_RESULT_MAP.md` to locate the frozen OOF metrics, eight score arrays, paired-bootstrap summaries, Kyushu metrics and exact-replay evidence under `reference_results/`. The hash checker verifies their distributed bytes; it does not recalculate them.

## B. Full scientific workflow — instructions for a future cleared package, **not currently runnable**

1. Obtain the rights-cleared, versioned data deposit described in `MINIMUM_PUBLIC_DATA_PLAN.md`; verify every SHA-256 before placement. The seven target relative paths are listed there. Do not download historical source replacements at current versions and assume equivalence.
2. Resolve the additional original `20A.preflight()` real pair table and registry after rights review. In this **local** candidate, the missing BASE-00 modules, frozen encoder module, exact-path metadata and original Hiroshima finalizer have been restored, and the seven key scripts pass import smoke. The byte-identical frozen 120B files are now also staged under `experiments/MSRR_CROSS_BACKBONE_5FOLD_V1B/` at the actual consumed paths. This does not establish a real-data run or complete the 124D-to-125 prediction hand-off.
   The formal 120B entry refuses to overwrite a nonempty output directory. A separately authorized rerun therefore needs a distinct clean execution checkout **without** this archived hand-off directory; preserve and hash-check the candidate's frozen copy rather than deleting or overwriting it. The downstream scripts may use the archived hand-off for input-layout inspection, but not as proof of a newly executed 120B run.
3. In a separate, authorized scientific rerun, check the full input gates and record environment/source hashes, seeds, fold membership and output paths. Only then consider the formal entry points in this order:

   ```bash
   python scripts/01_verify_inputs.py --full
   python scripts/127_AUDIT_MATCHING_PROTOCOL_REPRODUCIBILITY.py
   python scripts/130_AUDIT_ORIGINAL_BENCHMARK_EXACT_REPLAY.py
   python scripts/120B_RUN_MSRR_CROSS_BACKBONE_5FOLD_NO_LIGHTGBM_ONE_SHOT.py
   python scripts/121_RECOVER_OOF_AND_PAIRED_BOOTSTRAP.py
   python scripts/124D_RUN_KYUSHU2017_FROZEN_EXTERNAL_VALIDATION.py
   ```

   These are **not** lightweight review commands; they read real event data and the later commands train/evaluate models or perform formal inference. Their presence here maps the authority chain, not permission or evidence that they were run in this audit. `127`/`130` also require substantial intermediate/source data beyond the seven model-ready files.

## Interpretation and acceptance boundary

- RAW has 92 static plus 70 × 10 rainfall features = **792**; MSRR is **2446**. The transform uses shared set mean, signed and absolute deviations, and rainfall-residual summaries; it does not use roles/labels to construct features.
- Hiroshima has 5,056 complete 1-positive/2-hard-control sets and five spatial folds; Kyushu has 1,692 complete external sets. A hard control is not a verified permanent non-landslide location.
- AUROC/AUPRC use pooled row scores; StrictPair and Edge assess matched-set ordering. Frozen published values are in `reference_results/`, but independent confirmation requires the input and execution closure above.
- The present public candidate supports software inspection and light synthetic evaluation. It does **not yet** support independent regeneration of the main scientific results. Any data unavailability statement must give a real, source-specific reason and the best lawful access/reconstruction route; do not label all seven files restricted by default.
